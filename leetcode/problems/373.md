示例 1 的 $\textit{nums}_1=[1,7,11]$，$\textit{nums}_2=[2,4,6]$。如果把所有数对的和都算出来，可以得到一个矩阵 $M$，其中 $M_{i,j} = \textit{nums}_1[i] + \textit{nums}_2[j]$。

$$
M = \begin{bmatrix}
3 & 5 & 7       \\
9 & 11 & 13     \\
13 & 15 & 17    \\
\end{bmatrix}
$$

由于 $\textit{nums}_2$ 是递增的，所以矩阵**每一行都是递增的**。问题相当于：

- 给你 $n$ 个升序数组，请你合并这 $n$ 个升序数组，得到前 $k$ 小元素。（$n$ 是 $\textit{nums}_1$ 的长度）

这和 [23. 合并 K 个升序链表](https://leetcode.cn/problems/merge-k-sorted-lists/) 是一样的，请看 [我的题解](https://leetcode.cn/problems/merge-k-sorted-lists/solutions/2384305/liang-chong-fang-fa-zui-xiao-dui-fen-zhi-zbzx/) 的方法一。

算法如下（原理见 23 题）：

1. 首先，把矩阵每一行的第一个数 $M_{i,0}$ 及其在矩阵中的位置 $(i,0)$ 加到一个最小堆中。
2. 循环 $k$ 次。
3. 每次循环，弹出堆顶，把堆顶 $M_{i,j}$ 的对应数对 $(\textit{nums}_1[i], \textit{nums}_2[j])$ 加入答案。下一个最小值可能是 $M_{i,j}$ 的右边元素，把 $M_{i,j+1}$ 及其在矩阵中的位置 $(i,j+1)$ 入堆。

## 写法一

```py [sol-Python3]
class Solution:
    def kSmallestPairs(self, nums1: list[int], nums2: list[int], k: int) -> list[list[int]]:
        h = [(nums1[i] + nums2[0], i, 0) for i in range(min(len(nums1), k))]  # 至多 k 个
        # nums1 是递增的，无需堆化

        ans = []
        for _ in range(k):
            _, i, j = heappop(h)
            ans.append([nums1[i], nums2[j]])
            if j + 1 < len(nums2):
                heappush(h, (nums1[i] + nums2[j + 1], i, j + 1))  # 可能是下一个最小值
        return ans
```

```java [sol-Java]
class Solution {
    public List<List<Integer>> kSmallestPairs(int[] nums1, int[] nums2, int k) {
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
        for (int i = 0; i < Math.min(nums1.length, k); i++) { // 至多 k 个
            pq.add(new int[]{nums1[i] + nums2[0], i, 0});
        }

        List<List<Integer>> ans = new ArrayList<>(k); // 预分配空间
        while (k-- > 0) {
            int[] top = pq.poll();
            int i = top[1];
            int j = top[2];
            ans.add(List.of(nums1[i], nums2[j]));
            if (j + 1 < nums2.length) {
                pq.add(new int[]{nums1[i] + nums2[j + 1], i, j + 1}); // 可能是下一个最小值
            }
        }
        return ans;
    }
}
```

```go [sol-Go]
func kSmallestPairs(nums1, nums2 []int, k int) [][]int {
    n, m := len(nums1), len(nums2)
    h := make(hp, min(k, n))
    for i := range h {
        h[i] = tuple{nums1[i] + nums2[0], i, 0}
    }
    // nums1 是递增的，无需堆化

    ans := make([][]int, 0, k) // 预分配空间
    for range k {
        p := heap.Pop(&h).(tuple)
        i, j := p.i, p.j
        ans = append(ans, []int{nums1[i], nums2[j]})
        if j+1 < m {
            heap.Push(&h, tuple{nums1[i] + nums2[j+1], i, j + 1}) // 可能是下一个最小值
        }
    }
    return ans
}
```

## 写法二

也可以在循环的过程中把 $(i,0)$ 入堆。

由于一开始堆的大小不大，出堆入堆更快，整体效率更高。

```py [sol-Python3]
class Solution:
    def kSmallestPairs(self, nums1: list[int], nums2: list[int], k: int) -> list[list[int]]:
        h = [(nums1[0] + nums2[0], 0, 0)]
        ans = []
        for _ in range(k):
            _, i, j = heappop(h)
            ans.append([nums1[i], nums2[j]])
            if j == 0 and i + 1 < len(nums1):
                heappush(h, (nums1[i + 1] + nums2[0], i + 1, 0))
            if j + 1 < len(nums2):
                heappush(h, (nums1[i] + nums2[j + 1], i, j + 1))
        return ans
```

```java [sol-Java]
class Solution {
    public List<List<Integer>> kSmallestPairs(int[] nums1, int[] nums2, int k) {
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
        pq.add(new int[]{nums1[0] + nums2[0], 0, 0});

        List<List<Integer>> ans = new ArrayList<>(k); // 预分配空间
        while (k-- > 0) {
            int[] top = pq.poll();
            int i = top[1];
            int j = top[2];
            ans.add(List.of(nums1[i], nums2[j]));
            if (j == 0 && i + 1 < nums1.length) {
                pq.add(new int[]{nums1[i + 1] + nums2[0], i + 1, 0});
            }
            if (j + 1 < nums2.length) {
                pq.add(new int[]{nums1[i] + nums2[j + 1], i, j + 1});
            }
        }
        return ans;
    }
}
```

#### 复杂度分析

- 时间复杂度：$\mathcal{O}(k\log\min(n,k))$，其中 $n$ 为 $\textit{nums}_1$ 的长度。堆中至多有 $n$ 个三元组，但由于至多循环 $k$ 次，在 $k$ 很小的情况下三元组个数为 $\mathcal{O}(k)$，所以堆中有 $\mathcal{O}(\min(n,k))$ 个三元组。循环 $k$ 次，每次出堆入堆的时间复杂度为 $\mathcal{O}(\log\min(n,k))$，总的时间复杂度为 $\mathcal{O}(k\log\min(n,k))$。
- 空间复杂度：$\mathcal{O}(\min(n,k))$。堆中至多有 $\mathcal{O}(\min(n,k))$ 个三元组。
